VACANTES ESCOLARES - EJECUTAR LA ENTREGA COMPLETA
Google reCAPTCHA v2, excepciones de negocio, logs y auditoría
Revisado: 28/10/2026

1. QUÉ NECESITAS
================================================================
Para ejecutar el JAR preparado:
- Java 25 / JDK 25 instalado.
- MySQL Server 8.4 instalado y funcionando.
- Internet para cargar y validar Google reCAPTCHA.
- ZIP extraído, con vacantes-escolares.jar y el ejemplo de configuración.

Maven e IntelliJ sirven para editar o compilar el código. No hacen falta para ejecutar el JAR preparado.
El paquete no utiliza instaladores ni scripts .cmd o .ps1.

Descargas oficiales:
JDK 25: https://www.oracle.com/java/technologies/downloads/#jdk25-windows
MySQL 8.4: https://dev.mysql.com/downloads/mysql/8.4.html
Workbench: https://dev.mysql.com/downloads/workbench/
IntelliJ: https://www.jetbrains.com/idea/download/?section=windows
Maven: https://maven.apache.org/download.cgi

En una terminal nueva, java -version debe indicar 25.

2. PREPARAR MYSQL UNA SOLA VEZ
================================================================
En la instalación de MySQL, configura un servidor de desarrollo, TCP/IP en el puerto 3306 y una contraseña propia para root. Inicia el servicio MySQL.

En Workbench conéctate con root a 127.0.0.1:3306. Abre una pestaña SQL.
Cambia el marcador de contraseña por una clave propia y ejecuta todo el bloque:

CREATE DATABASE vacantes_escolares
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'vacantes_app'@'127.0.0.1'
  IDENTIFIED BY 'REEMPLAZAR_POR_UNA_CLAVE_PROPIA';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, INDEX, REFERENCES
  ON vacantes_escolares.* TO 'vacantes_app'@'127.0.0.1';

La aplicación usará vacantes_app y la contraseña que acabas de elegir, no la contraseña root.
Si la base o el usuario ya existen, utiliza sus datos y revisa sus permisos.
No ejecutes manualmente los SQL de db/migration: Flyway crea y actualiza las tablas al iniciar.

3. OBTENER LAS CLAVES DE GOOGLE UNA SOLA VEZ
================================================================
Abre https://www.google.com/recaptcha/admin/create
- Registra un sitio de desarrollo de tipo reCAPTCHA v2.
- Selecciona la casilla "No soy un robot".
- Autoriza localhost y 127.0.0.1, sin http://, rutas ni puerto.
- Conserva la clave del sitio y la clave secreta para la configuración de tu PC.

Google es el modo predeterminado. Sin sus claves la aplicación no inicia; no cambia automáticamente al CAPTCHA de números.

4. CONFIGURAR LA PC UNA SOLA VEZ
================================================================
En la carpeta del proyecto, copia application-local.properties.example.
Cambia el nombre de la copia a application-local.properties.
Comprueba que Windows no añada .txt al final del nombre.

Abre la copia con un editor y completa los valores vacíos:

spring.datasource.username=vacantes_app
spring.datasource.password=TU_CONTRASENA_MYSQL
app.seed.admin-password=TU_CLAVE_ADMIN_MINIMO_10_CARACTERES
app.seed.admissions-password=TU_CLAVE_ADMISIONES_MINIMO_10_CARACTERES
app.seed.guardian-password=TU_CLAVE_APODERADO_MINIMO_10_CARACTERES
app.seed.other-password=TU_CLAVE_OTRO_APODERADO_MINIMO_10_CARACTERES
app.captcha.mode=google
app.captcha.site-key=TU_CLAVE_DEL_SITIO_GOOGLE
app.captcha.secret-key=TU_CLAVE_SECRETA_GOOGLE
app.captcha.allowed-hostnames=localhost,127.0.0.1

Los textos TU_... son marcadores: sustitúyelos por tus valores. El ejemplo distribuido deja los campos secretos vacíos.
Las cuatro contraseñas app.seed son para entrar en el portal y deben tener al menos 10 caracteres. No son la contraseña MySQL.
Si una clave contiene una barra invertida, escríbela duplicada en un archivo .properties.
El archivo local no se comparte ni se publica en Git. El proyecto no carga .env automáticamente.

5. EJECUTAR EL PORTAL
================================================================
Inicia MySQL. Abre una terminal en la carpeta de vacantes-escolares.jar y application-local.properties.
Ejecuta esta línea completa:

java -jar vacantes-escolares.jar --spring.config.additional-location=file:./application-local.properties

Espera "Started VacantesApplication" y abre http://127.0.0.1:8087
Para detener: Ctrl+C en esa terminal.
Las siguientes veces se conservan la base y el archivo local: solo inicia MySQL, ejecuta el mismo comando y abre el navegador.

El primer inicio crea tablas mediante Flyway, ofertas por grado y tres solicitudes ficticias. No copia los datos registrados en otra PC.

CUENTAS DEL PORTAL
admin@colegio.test       -> contraseña de app.seed.admin-password
admisiones@colegio.test  -> contraseña de app.seed.admissions-password
apoderado@colegio.test   -> contraseña de app.seed.guardian-password
otro@colegio.test        -> contraseña de app.seed.other-password

El inicializador solo crea cuentas que no existen. Cambiar una propiedad después no cambia la contraseña de una cuenta ya guardada.

6. VER TABLAS Y LOGS
================================================================
En Workbench crea una conexión a 127.0.0.1:3306 con usuario vacantes_app y su contraseña MySQL. Selecciona vacantes_escolares como esquema.
Despliega SCHEMAS > vacantes_escolares > Tables.

Para comprobar la estructura:
USE vacantes_escolares;
SHOW TABLES;
SELECT COUNT(*) AS ofertas FROM academic_offers;

En una base nueva de demostración se preparan 13 ofertas.

Los logs se conservan en logs/vacantes-escolares.log, relativo a la carpeta de ejecución. Se rotan para limitar el tamaño de los archivos.
La tabla audit_events conserva actor, acción, referencia, detalle, fecha, nivel (level) e IP de origen (origin_ip).
Los rechazos de negocio quedan auditados aunque no se complete la operación.

7. RECORRIDO FUNCIONAL PARA EL PARCIAL (UNOS 7 MINUTOS)
================================================================
- Muestra Google reCAPTCHA en el registro y el acceso con roles.
- Como apoderado, consulta las solicitudes y corrige una observada.
- Como admisiones, revisa la solicitud y comunica un resultado.
- Intenta crear una solicitud activa duplicada y muestra el mensaje amigable.
- Como administrador, consulta auditoría y compara el evento con el archivo de logs.

También hay excepciones para solicitud inexistente, falta de vacantes y estados que ya no admiten cambios.
La clase 6 pide mostrar dónde se aplican los mecanismos; no exige informe ni PPT. El profesor puede preguntar sobre código.

8. EDITAR O COMPILAR
================================================================
Necesitas JDK 25, Maven 3.9 e IntelliJ IDEA.
Abre la carpeta de pom.xml como Maven, confía en este proyecto y selecciona JDK 25.
Si aparece la casilla de exclusiones de Microsoft Defender, déjala desmarcada.
Espera la sincronización de dependencias.

En la carpeta de pom.xml:
mvn test
mvn package

Las pruebas usan H2 en memoria. El JAR nuevo queda en target/vacantes-escolares.jar.
Para ejecutarlo con tu archivo local:

java -jar target/vacantes-escolares.jar --spring.config.additional-location=file:./application-local.properties

También puedes copiar el JAR nuevo a la raíz para usar el comando corto de la entrega.

Desde IntelliJ: Run > Edit Configurations > Application.
Main class: pe.edu.vacantes.VacantesApplication
JRE: JDK 25
Working directory: carpeta de application-local.properties
Program arguments:
--spring.config.additional-location=file:./application-local.properties

9. SI APARECE UN ERROR
================================================================
Java 25 no compatible / release 25: revisa java -version, JDK del proyecto y JRE de ejecución.
Connection refused: inicia MySQL y comprueba el puerto 3306.
Access denied: revisa usuario, contraseña y permisos de vacantes_app@127.0.0.1.
Unknown database: crea la base vacía vacantes_escolares.
Faltan claves reCAPTCHA: completa app.captcha.site-key y app.captcha.secret-key.
Faltan claves demo: completa las cuatro app.seed.*-password con al menos 10 caracteres.
No encuentra el archivo local: revisa la carpeta de ejecución y que el nombre no termine en .txt.
Puerto 8087 ocupado: detén otra instancia o cambia server.port en el archivo local y abre ese puerto en el navegador.
